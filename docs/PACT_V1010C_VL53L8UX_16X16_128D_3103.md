# PACT-128D: idealized L8UX-inspired 16×16 sensor-profile evaluation

Created 2026-09-18. Seed 3103, 50 matched source scenarios, no training or normalization refit.

## Scope and interpretation

Evaluate the existing jointly fine-tuned PACT-128D checkpoint with a new native
16×16 simulated range grid and a fixed 2×2 minimum-pooling adapter to the encoder's
8×8 input. The policy and encoder remain frozen. All forty sensor mounts and their
order remain unchanged.

This is an **idealized L8UX-inspired profile study**. ST's public presentations
establish the model name and several headline specifications, but a detailed
public datasheet, driver, and calibrated measurement model were not verified.
Do not describe the outcome as validated VL53L8UX hardware performance.

The primary reference is original seed-3103 PACT (27/50 placement, 24/50
collision-free placement). The already audited ACT pair (19/50 placement,
16/50 collision-free placement) provides descriptive context on the same scenes.
Both references are historical, not new runs. Comparisons with the L7CX studies
are also descriptive. Multiple sensor parameters change relative to source PACT;
this study cannot isolate the effect of increasing resolution.

## Evidence and fixed measurement choices

Sources consulted on 2026-09-18:

- [ST CES 2024: Immersive Ski Game, pages 5–6](https://www.st.com/content/dam/static-page/events/ces-2024/23-immersive-ski-game.pdf): 256-zone output, advertised 60 fps capability, 3 m range, and portfolio entry for VL53L8UX with 16×16 zones and 65° FoV.
- [ST Industrial Summit 2024, page 6](https://www.st.com/content/dam/OLM%20Email%20Marketing/2024/Asia%20Pac/Event/industrial-summit-2024/track-3-automation/en/a3-03-imaging-3d-sensing-and-iot-solutions-approved.pdf): 16×16 zones, 65° FoV, 300 cm in darkness.

| Parameter | Executed value | Evidence or assumption |
|---|---|---|
| Native spatial grid | 16×16, 256 independent ideal render pixels | Resolution documented; one ideal central ray per zone is a simulation approximation |
| Field of view | 48.5009095° horizontal and vertical | Assume the listed 65° is diagonal and use a square pinhole: `2 atan(tan(65°/2)/sqrt(2))`; exact L8UX angular map unverified |
| Native acquisition | 15 Hz | Experimental choice consistent with earlier L7CX runs; ST advertises 60 fps capability, but a selectable-rate API was not verified |
| Minimum distance | 2 cm saturation | Retained simulation convention; L8UX near-range specification unverified |
| Maximum distance | 3 m; farther returns become 3 m | Fixed approximation of advertised dark-range capability; no reflectance/ambient dependence |
| Output rounding | 1 mm | Experimental convention, not a claim of hardware accuracy or firmware encoding |
| Distance convention | Optical-axis depth | Consistent with prior multizone simulations; L8UX firmware behavior unverified |
| Acquisition clock | Reset frame, then first 2 ms physics tick at/after each `k/15` deadline | Causal clock with no accumulated rounding drift |
| Existing observation interface | Four held polls at 16, 32, 48, 64 ms per 66 ms control interval | Retain original controller interface and temporal minimum pooling |
| Shape adapter | Minimum of each nonoverlapping 2×2 block, after clipping/rounding | Fixed before new scientific outcomes; 16×16 becomes 8×8 |
| Physical metadata | Intrinsics describe the native 16×16 renderer | Encoder's original internal calibration and preprocessing remain unchanged |
| Unmodeled effects | Noise, SPAD response, integration, firmware target selection, crosstalk, bus/readout latency | No physical-fidelity claim |

For encoded native distances `D`, the policy receives
`P[y,x] = min(D[2*y:2*y+2, 2*x:2*x+2])`, for `y,x = 0,…,7`.
Every native cell participates once. Below-range returns retain the 2 cm floor;
they are not discarded as empty space. Entirely above-range blocks remain 3 m.
The adapter is not fitted, and no alternative pooling operator is selected from
evaluation performance. Although 256 values are acquired, only 64 derived values
reach the original encoder per sensor and observation poll.

## Preflight and audit

1. Run targeted tests covering spatial-block identity, below/above-range behavior,
   causal acquisition timing, real MuJoCo rendering of a thin obstacle, unchanged
   geometry/wrist camera, forbidden initial-state changes, statistical decisions,
   and technical versus scientific failure handling.
2. Verify complete model/encoder loading and all saved source identities.
3. Replay 105 training frames through the original and wrapped controllers;
   require exactly matching actions/readouts and reset behavior.
4. Exercise ten synthetic adapted histories with unchanged model state.
5. Execute ten real-scene interface steps; verify native 16×16 frames, correct
   8×8 delivery, initial pairing, and unchanged inference weights. These ten
   steps are infrastructure checks, excluded from scientific outcomes.
6. Freeze the profile, scenario schedule, implementation hashes, tests,
   preflight receipts and statistical procedure before scientific outcomes.
7. Run the first full scientific scenario as a technical gate, then continue
   with up to six workers. The first scenario stays in the fifty regardless of
   success. Preserve all attempts; one technical retry only for a declared
   transient error or a one-hour worker timeout. Never retry a scientific failure
   to obtain success. Unresolved technical failures make the study incomplete.
8. Save native `(892,40,16,16)` and pooled `(892,40,8,8)` arrays per full rollout,
   timestamps, delivery indices and the hash of all consumed encoder inputs.
   Before completion, independently recompute all 64 block minima, rebuild all
   900 consumed input tensors, verify their hash, and recompute task/contact metrics.

The worker verifies unchanged policy and encoder state after inference. Full
trajectories, contact telemetry and initial observations are retained. No earlier
study files or hash-bound scripts are overwritten.

## Outcomes and statistical procedure

Primary: collision-free placement over the entire 900-action rollout. Forbidden
classes are hazard bar, clutter, other environment and mounted fixture; intended
grasp-target and place-receptacle contacts remain allowed. Separately report task
completion, touch, lift, contact incidence, collision-free rollouts, contact
samples and contact exposure. Samples are not independent trials.

Compare each scenario with its original PACT result. Use exact two-sided McNemar
tests and descriptive paired bootstrap intervals with 20,000 scenario resamples,
seed `2026091801`. Preserve the prior studies' prespecified maximum acceptable loss
of 10 percentage points. A conservative one-sided 95% lower bound above −10 pp
supports retention; an upper bound below −10 pp establishes loss exceeding the
margin; otherwise report inconclusive retention. These bounds combine one-sided
97.5% Clopper–Pearson components for paired gains/losses. Nonsignificance alone
never establishes retention. Report missing/censored data and per-scene outcomes.

This is another exploratory study selected after earlier sensor results, with one
training seed and shared references. Report unadjusted tests as exploratory; do
not claim a new independently confirmed family of sensor-transfer effects.
Positive results would support this particular frozen system under its declared
simulation and adapter. Negative results identify a limitation of that combination.
Neither outcome demonstrates physical hardware transfer or a causal effect of
encoder fine-tuning, increased resolution, or individual sensor parameters.
