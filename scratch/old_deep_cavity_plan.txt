0. ONE-PARAGRAPH GOAL
---------------------
Build a NEW MolmoSpaces datagen task that forces the Franka FR3 (with the 40-sensor
HYBRID proximity skin) to EXTEND DEEP into an enclosed two-level "fridge", grasp ONE
object resting at the back of the deep UPPER compartment, retract, and PLACE it onto a
fixed target zone on the open LOWER shelf. Walls are PHYSICAL and tight, so collision-
checked planning is required and the whole-body proximity skin is genuinely necessary
(not decorative). One item only for now (no clutter); clutter is a later extension.

This reconstructs + extends work lost on a dead machine. The lost piece was a config
named `FrankaSkinOpenFrontClutteredReachPickAndPlacePilotConfig` (imported by
scratch/run_datagen.py) that never got pushed and does NOT exist in the cloned
molmospaces. We are rebuilding that lineage, cleaner, as a deep two-level fridge.

DESIGN DECISIONS (locked with the user 2026-06-27):
  - Walls: PHYSICAL + tight (proximity genuinely necessary; collision-checked planning).
  - Place target: FIXED ZONE on the lower shelf (deterministic goal pose, not a receptacle).
  - Geometry: TWO-LEVEL FRIDGE (deep upper compartment = pick; open lower compartment = place).

2. THE GEOMETRY TO BUILD  (custom_scenes/fridge_two_level.xml)
--------------------------------------------------------------
Coordinate convention (inherited from cabinet_cavity.xml): robot base near world origin
on a pedestal, +x faces the opening; the fridge sits in front at x ~0.3..0.86; world z is
height. All <size> values are HALF-extents. Walls PHYSICAL (class "cavity_struct" from
cabinet_cavity.xml: contype=8 conaffinity=15, friction, solref/solimp, density 800).

STARTING dimensions (MUST be validated + tuned in step 4 -- treat as a first cut):
  Outer envelope: x in [0.34, 0.84] (depth ~0.50), y in [-0.30, 0.30] (width 0.60).
  - cab_back   : physical wall at x=0.85   (z spanning both levels)
  - cab_left   : physical wall at y=+0.31
  - cab_right  : physical wall at y=-0.31
  - cab_top    : physical wall at z=1.05
  - cab_floor  : physical bottom at z=0.38  (lower-shelf support surface; object placed here)
  - cab_mid    : physical horizontal SHELF at z=0.70  (divides upper/lower; UPPER floor)
  - front: OPEN on -x for BOTH levels so the arm enters. Optional thin lower front lip at
    z~0.40 so the placed item can't roll out.
  UPPER compartment (the PICK): interior x in [0.36,0.83], z in [0.72,1.03], y[-0.28,0.28].
    Item rests DEEP + HIGH at ~(0.64, 0, 0.74) so the arm must fully extend in and up ->
    the 40 sensors get encapsulated by mid-shelf (below), top (above), back, and sides.
  LOWER compartment (the PLACE): interior x in [0.36,0.83], z in [0.40,0.68].
    Fixed place zone = a small STATIC "place pad" BODY near the FRONT-CENTER (NOT a site --
    the place planner needs a real body whose AABB it can read; see section 3):
      <geom name="place_pad" type="box" pos="0.50 0 0.39" size="0.06 0.06 0.01"
            rgba="0.2 0.7 0.2 1" contype="8" conaffinity="15"/>
    Pad top ~z=0.40. The planner sets the object DOWN centered on this pad. Keep the pad
    small so the "zone" is well localized but big enough that the object rests stably.
    The sampler registers this pad as the place receptacle (section 3).

WHY this shape maximizes proximity: the pick pose buries the wrist + forearm inside a
box bounded on 5 of 6 sides within ~0.15-0.28 m, so nearly all 40 sensors read < 0.5 m
through the approach/grasp; and because the walls are PHYSICAL the collision-checked
planner must thread the arm in/out using those clearances -> proximity is causally load-
bearing for success, not redundant with vision.

Add fridge_two_level_metadata.json next to it (copy cabinet_cavity_metadata.json).


3. THE TASK SAMPLER  (tasks/cavity_pick_task_sampler.py, new subclass)
----------------------------------------------------------------------
RESOLVED (was an open risk; I read pick_and_place_planner_policy.py end-to-end):
The place is a CONTROLLED SET-DOWN, not a drop -- exactly what the user wants. The
PickAndPlacePlannerPolicy trajectory is:
   open gripper -> pregrasp -> grasp -> CLOSE -> lift -> preplace (hover ABOVE the pad)
   -> place (lower until the object's BOTTOM is at the pad's TOP surface) -> OPEN gripper
   -> retreat up -> go home.
It computes the place height from the place receptacle's AABB top
(_get_placement_poses: receptacle_top_z = aabb_center.z + aabb_size.z/2; place_pose.z =
receptacle_top_z + object_clearance) and even shifts the EE so the OBJECT (not the gripper)
lands centered over the receptacle xy. So it sets the item down gently and centered -- not
super-precise, exactly the "you get what I mean" the user described.

KEY CONSEQUENCE: the planner needs a real place receptacle BODY (it reads
task_config.place_receptacle_name from the object manager and takes that body's AABB). It
does NOT accept a bare xyz goal. That is why the lower-shelf "fixed zone" is the small
STATIC place_pad BODY from section 2 -- we register that pad as the place receptacle.

So the new sampler combines two existing machineries:
  (A) custom-scene + single-object injection (from CavityPickTaskSampler), and
  (B) the pick-AND-place pipeline + place success (from PickAndPlaceTaskSampler).

RECOMMENDED IMPLEMENTATION: new class FridgePickAndPlaceTaskSampler(PickAndPlaceTaskSampler).
Re-use the THREE short custom-scene overrides from CavityPickTaskSampler (copy them; they
are ~10 lines each):
  1. add_auxiliary_objects -> inject the ONE grasp-validated objaverse pickup object DEEP in
     the upper compartment (reuse CavityPick's _uid_pool + shape filter + install_uid + the
     metadata_adder registration). THEN also register the place target: the place_pad is a
     static geom already in the XML -- make sure the object manager knows it (inject it as a
     static body the same way, or add a metadata entry) and remember its name.
  2. _get_dataset_index_map -> custom "user" scene: map every variant (base/ceiling/map) to
     the one fridge XML (verbatim from CavityPick).
  3. _sample_and_place_robot -> set the robot base pose DIRECTLY (custom scenes have no
     occupancy map). Verbatim from CavityPick, plus set:
         task_config.pickup_obj_name      = injected object name
         task_config.place_receptacle_name = "place_pad" body name   <-- drives place + success
Disable/skip PickAndPlaceTaskSampler's house-receptacle DISCOVERY (we supply the pad, so
do not let it search the scene for objaverse receptacles). Check _on_candidate_selected /
_add_receptacles_to_scene in the PnP sampler and short-circuit them to use our pad.

Constants for the subclass:
      CAVITY_CENTER  = (0.60, 0.0, 0.87)     # upper compartment center (match XML)
      CAVITY_INTERIOR= (0.24, 0.27, 0.16)    # upper interior half-extents (match XML)
      OBJ_XY         = (0.64, 0.0)           # deep + back: full extension on the pick
      OBJ_FLOOR_Z    = 0.72                  # top of the mid shelf (upper compartment floor)
      OBJ_JIT_XY     = (0.05, 0.07)
      PLACE_PAD_NAME = "place_pad"           # the static pad body from the XML (section 2)
_settle_injected_object must settle the pickup object onto the UPPER mid-shelf
(OBJ_FLOOR_Z=0.72) -- make _obj_rest() return the upper spot.

Place SUCCESS: scored in tasks/pick_and_place_task.py (object-to-place-target distance under
task_config.task_success_threshold). Because place_receptacle_name = our pad, success ==
"object ended up resting on the pad". Read pick_and_place_task.py once to confirm the
threshold + that filter_for_successful_trajectories keeps only those.

Tuning knobs if the planner stalls in the tight physical box: policy_config.place_z_offset,
pregrasp_z_offset, grasp filtering (filter_colliding_grasps / filter_feasible_grasps), and a
V2 scene with a slightly wider mouth. Validate with section 4 after any geometry change.
